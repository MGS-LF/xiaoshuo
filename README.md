# 墨线 · 小说工坊

一个本地运行的网页版小说生成器。项目、大纲、章节正文与上下文记忆持久化到 SQLite，大模型通过 OpenAI 兼容接口接入。

## 启动

```bash
npm install
npm start
```

打开 `http://localhost:3000`，在左下角“模型设置”中填写接口地址、API Key 和模型名。

支持 OpenAI、DeepSeek、通义千问、智谱、硅基流动，以及提供 OpenAI 兼容接口的本地服务。Ollama 通常可填写 `http://localhost:11434/v1`，本地接口允许不填 API Key。

## 写作流程

1. 输入书名、类型、主题、章数、每章字数和文风。
2. 生成世界设定、主要人物、时间线、大体剧情与逐章大纲。
3. 分块审核并修改大纲，确认后进入写作台。
4. 逐章生成或连续写作，完成后可导出 TXT。

单部作品最多支持 1000 章。超过 50 章时，系统先规划全书分卷和阶段节奏，再按每批 20 章顺序生成逐章大纲。页面实时显示批次和百分比，每个成功批次都会保存到 SQLite；模型返回的 JSON 会自动修复常见格式错误，无法修复时仅重试当前批次最多 3 次。任务失败或服务重启后可从失败批次继续。

任意作品顶部的“衍生创作”支持两种新建方式：

- 写后续：携带原作全局摘要、人物、世界设定与最近结尾，创建独立续作草稿。
- 复用模板：复用类型、篇幅、文风和自定义设定，不复制原作正文与剧情。

创建作品或生成大纲前可以选择系统内其他作品作为参考，并选择大体逻辑、相似文风、结构扩充或综合参考。模型只提炼抽象结构与风格特征，不复用参考作品的人名、具体事件和原句。

写作台中的“重规划后续”可以指定起始章节、新总章数和调整要求。起始章之前的正文、大纲和记忆保持不变；起始章及之后会重新生成章节标题、大纲、未来时间线、剧情方向和必要的新人物。

## 上下文策略

- 每章完成后生成结构化章节摘要和人物、剧情、伏笔、地点、物品记忆。
- 长章节先按段摘要，再归并为章节记忆，避免截断章末情节。
- 全局摘要滚动更新，控制在固定长度内。
- 写下一章时仅注入全局摘要、最近五章摘要、上一章末尾、相关时间线、人物和关键记忆。
- 强制按章节顺序生成，避免缺少前序状态导致剧情跳跃。

数据库文件位于 `data/novels.db`。API Key 同样保存在本机数据库中，请勿将数据库文件提交或分享。

## CNB 自动构建与容器启动

推送到 `main` 后，CNB 会自动安装依赖、执行测试、启动应用检查健康状态，并发布以下两个镜像标签：

- `docker.cnb.cool/tvtink/xiaoshuo:latest`
- `docker.cnb.cool/tvtink/xiaoshuo:<提交短哈希>`

在部署服务器上运行最新版，并持久化数据库：

```bash
docker run -d \
  --name xiaoshuo \
  --restart unless-stopped \
  -p 3000:3000 \
  -v xiaoshuo-data:/app/data \
  docker.cnb.cool/tvtink/xiaoshuo:latest
```

仓库同时配置了 CNB 仅预览模式。在分支页面点击“云原生开发”后，CNB 会自动安装依赖、在 `8686` 端口启动应用并直接打开网页，不需要进入 WebIDE。预览环境启用了数据备份和 1 小时离线保活。
